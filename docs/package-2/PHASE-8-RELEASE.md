**How the figures are made:**
- Each figure is drawn as code (inline SVG) from its equation (Michaelis–Menten, Hill curves, normal density, Henderson–Hasselbalch), so curves are exact and sharp at any size.
- They're generated by `tools/graphics-build/make.py`.
- Each has a `<title>` and a written `<desc>` as its text alternative.
- Labels were checked visually at phone and desktop widths, and three label collisions were fixed.

**IDs:** new IDs in the form `<category>-Gnn`. The original 1,000 cards are untouched (`check-cards` passes).

**Content still to check:** a content expert should still confirm wording and accuracy. Points worth a second look:
- The X-linked pedigree is "best fits": autosomal recessive isn't strictly impossible from one family.
- The phase diagram is labeled as water's.

## 8.2 Same card interface

- **No redesign:** the cards use the existing card component (same header, cursive label, footer, buttons, flow). The figure is simply part of the question content.
- **Figure size:** figures scale to the card width (up to 440 px), and appear smaller above the question on the answer side.
- **Tested:** they fit at 360 px and 1280 px with no sideways scroll (`tests/phase8-browser.test.js`).

## 8.3 Concepts and mastery

- **Concept links:** every draft links to an AAMC concept in the Package 1 catalog. Records are in `metadata/graphic-cards.json` (status `draft_pending_owner_review`), and the cards are included in the site's embedded concept index.
- **Mastery:** card mastery is tracked per card, as for every card. Concept-level evidence on My Weaknesses counts each concept at most once (Phase 4), so a picture card on the same concept as a text card **can't inflate** the concept's estimate.

## Validation and publishing

- **The validator:** `node tools/validate-graphics.js` checks:
  - new unique IDs that don't collide with originals;
  - a valid category and matching section;
  - a concept that exists in the catalog;
  - a matching metadata record;
  - every figure with `role="img"` and a non-trivial title and description;
  - balanced SVG markup;
  - no placeholder text.
- **Approval gate:** a card listed in `GRAPHICS_PUBLISHED` **fails the check** unless its metadata says `"review_status": "approved"` with `"approved_by"`. The validator now runs in GitHub Actions and in the Vercel build, so an unapproved card can't be deployed.
- **To publish after review:**
  1. Set `review_status` to `"approved"` and add `"approved_by"` for each approved card in `metadata/graphic-cards.json`.
  2. Add their IDs to `GRAPHICS_PUBLISHED` in `index.html`.
  3. Push.
  4. Any card that needs changes is edited before step 2.

## Data changes and rollback

- **Data:** new `GRAPHIC_CARDS` / `GRAPHICS_PUBLISHED` in the page and `metadata/graphic-cards.json`. No student data changes and no database change.
- **Rollback:** revert this commit or promote the previous deployment. Nothing is published, so students see no difference.
